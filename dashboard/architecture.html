Slums MC — Autonomous Turtle Fleet

Architecture overview and first steps. Josh's private server, CC:Tweaked 1.120.2 on NeoForge 1.21.1, 303 mods.

What we're building

A fleet of turtles that report for duty, survive unattended operation across days, and can be supervised from a control center inside the world — with most supervision automatable from outside it.

What we're deliberately not building: total self-sufficiency with nobody in the world. Turtles halt on chunk unload, max_websockets is 4, and AdvancedPeripherals is alpha. High autonomy, not total.

Why this shape

DecisionReason
Wired modems Vanilla CC wired networks have no length cap and turtles can use them. Wireless caps at 64 blocks and degrades in thunderstorms. No extra mod needed.
In-world control center first DirectGPU works with zero network. That removes the tailnet-vs-LAN decision from the critical path entirely.
Dumb, expendable turtles AP has no pathfinding and chunkAnalyze returns counts without coordinates. So the controller owns the map and turtles just sense and execute. That also makes replacement-on-death correct.
Idempotent job ids A retry must replay, never re-execute. Otherwise a network blip makes a turtle dig the same tunnel twice.

Phases

Each phase ends in something observable. Nothing assumes a later phase worked.

  1. Transport — DONE
  2. One computer, one turtle, one job — NEXT heartbeat visible, one move command executes, socket closed cleanly
  3. Job board — queue.json round-trip, idempotent ids proven by a deliberate duplicate submit
  4. Capability — weak_automata dig, geo_scanner census, Radio GPS verified for position
  5. Force-load survival — the autonomy test a turtle works a chunk outside view and does not halt
  6. Rookie dispatcher — death → replacement, end_automata recall for refuel
  7. Control center — DirectGPU + Spatial Projector read telemetry/fleet.json
  8. Logistics — me_bridge/rs_bridge transfer, turtles as haulers into Create pipes

First steps — in the world

1. Confirm the computer

Which computer ID you're at. Computer 5 was empty; 4 holds the earlier rednet console.

2. Install the fleet modules

One file at a time, each paste self-contained. Start the file, paste the body, finish with a blank line:

shell.run("cat > /fleet/errors.lua")

3. Configure the controller

In /fleet/config.lua: MODE = "controller", BRIDGE_ENABLED = true. Bridge token goes in /bridge-token.txt — never typed into Lua.

4. Prove the heartbeat

Computer alone, no turtle. A heartbeat in telemetry/fleet.json is the whole goal. That path already worked once, so it should be quick.

Things that will bite

TrapWhat happens
silent A turtle one chunk outside the force-loaded set halts with no error. Check this first when a turtle goes quiet.
slots max_websockets=4 is global. An abandoned socket consumes one until the peer restarts.
scope CC shell: each line is a separate program. local does not survive between lines.
blocking ws.receive() blocks the coroutine and the computer looks frozen. Timeouts are milliseconds.
decoy cc-cbc is Create Big Cannons compat, not a cable mod. cc_sable is physics compat.
